# Native deep audit, November 3, 2026

This audit examined Android Compose photo input and solve state, SwiftUI photo input and review visibility, iOS Keychain replacement, local storage, and the corresponding test boundaries. All changes are on `rebuild/native-from-scratch`. The legacy `main` branch remains untouched.

## Findings and corrections

| Severity | Finding | Root cause and correction | Evidence |
| --- | --- | --- | --- |
| High | A failed iOS API-key replacement could delete a working key. | `KeyVault.save` deleted first and ignored the subsequent add status. Use `SecItemUpdate` for an existing item, add only when not found, check status, and show a write failure. | `formal/KeyVaultReplacement.tla`, workflow 41633320933 |
| Medium | Older photos or errors could overwrite a newer choice or reappear after removal. | Async decoder callbacks had no request identity. Android now uses `PhotoInputSession`; iOS invalidates prior imports with a revision counter and clears the old answer when a photo is chosen. | `formal/PhotoSelection.tla`, workflow 41631078255; Android CI 41631537236 and emulator 41631537177 |
| Medium | A new iOS review question could inherit the previous answer reveal. | Review UI held a single Boolean across changing due questions. Bind the reveal to the current question ID and reset when the due item changes. | `formal/ReviewVisibility.tla`, workflow 41632372061; failing real-app test 41632459399; fix commit 175a348 |
| Medium | iOS photo preparation could decode a large image on the UI thread. | Earlier `UIImage(data:)` work ran inside a main-actor task. ImageIO now builds a thumbnail at up to 2200 pixels off the main thread, with 30 MB input and 6 MB JPEG output limits. | `ios/DoubtBuddy/AskView.swift`, commit e1594db |

## Formal model checks

Each specification is checked with pstack `statechart` and TLC 1.7.4. The scripts prove that legacy transitions violate named safety rules, then check the corrected transitions without weakening the rules.

| `ReviewVisibility.tla` | Reveal an answer, then switch to a different due question | 4 states and 8 transitions, all declared checks hold, run 41632372061 |
| `KeyVaultReplacement.tla` | Delete an old key, then fail to add the new key | 4 states and 5 transitions, all declared checks hold, run 41633320933 |

Rerun the individual model checks:

```sh
bash scripts/verify-solve-statechart.sh
bash scripts/verify-photo-statechart.sh
bash scripts/verify-review-statechart.sh
bash scripts/verify-keyvault-statechart.sh
```

The models are finite abstractions. They do not prove the correctness of SwiftUI's rendering scheduler, Android activity results, actual Keychain implementation, external Gemini behavior, disk-write failures, or process death. They do prove the checked invariants for their enumerated states and transitions. The real-app tests provide independent evidence.

## Runtime results

Android unit and build CI passed in run 41631537236. Android emulator run 41631537177 passed 10 of 10 instrumented tests, including gallery removal and history persistence after process restart.

The iOS regression run 41632459399 reproduced the stale review reveal. Run 41754599696 passed 5 of 5 iOS UI tests after the fix, including review visibility, Keychain save/remove, question editing, and saved-answer persistence across app relaunch.

The apparent Saved regression was traced through the failed XCTest accessibility tree to a keyboard obstructing tab interaction. The Ask tab remained selected when the test attempted to open Saved. `AskView` now dismisses keyboard focus before Solve, and the test checks Saved navigation separately from exact question persistence. The iOS CI test target also generates an `Info.plist` for the ad-hoc-signed simulator bundle. Both fixes are verified by run 41754599696. Actual iOS gallery interaction and Keychain write-failure handling have not been tested on a physical device.

## Remaining risks

- iOS `StudyStore.persist()` swallows encoder and disk-write errors. It can report a saved answer even when a write fails. This audit did not validate a safe transactional replacement for that code.
- Android blocking `HttpURLConnection` calls are not guaranteed to abort immediately on coroutine cancellation. A canceled solve could still consume network resources.
- Android stores a completed answer on a background database dispatcher. A cancellation racing the database commit is not covered by the existing solve statechart.
- Device-memory measurements, real authorized Gemini inference, physical camera/gallery behavior, and signed release builds remain unverified.

Do not infer a production-readiness or speedup claim from these bounded model results.
